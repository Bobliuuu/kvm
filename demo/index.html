One persistent kernel, three workloads

KVM interprets a task DAG on every SM of an A100 (108 SMs). Below: GPT training, GPT serving on the weights training just published, and real Doom run in one kernel launch. Every picture is drawn from the executor's own per-task timestamps (%smid, %globaltimer) or from the run's outputs.

Read this first. This is a correctness-and-coexistence demo on a tiny model, not a speed claim. The GPU is mostly idle here (a few busy SMs of 108). The VM loses to a whole-step CUDA graph on the same small models (3.9-5.4x slower), and its ops reach 0.26-0.39x of cuBLAS. Run: NVIDIA A100-SXM4-40GB, 108 SMs, 27003 tasks in 4231 ms, all checks passed (executor, versions, training, serving, game, cadence).

Where each task ran, dynamic vs static

Same demo, same binary, only --sched differs. Static = fixed 70/10/20 SM split; dynamic = classes share all SMs by weight. Tasks are not preemptible: sharing happens at task boundaries.
